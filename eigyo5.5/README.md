# 営業AI v5.5

売り込む方法を増やすのではなく、「自然に会える理由」「相手にとっての期待値」「小さな次の一歩」を準備する関係起点の営業支援MVP。発表後のフィードバックを踏まえ、公開画面(カード・詳細)の情報量と視認性を整理したv5.5。

- 公開画面: https://masato19870410.github.io/ncbc/eigyo5.5/
- v4・v5は変更しない。
- v5.5の公開画面は、v4・v5と同じ公開Googleシートを読み取り専用で利用する。
- 個人の関係情報、営業履歴、メール、予定は公開画面へ送らない。

## 構成

| 場所 | 役割 |
|---|---|
| `index.html` | 現行10社を「会う理由」から比較する公開画面 |
| `gas-code.js` | 週次調査、本人通知、承認後のGmail下書き・予定作成 |
| `appsscript.json` | Apps Scriptの権限とタイムゾーン |
| `設計レビュー.md` | 現行評価、提供形態比較、MVP、検証方法 |

## 公開画面

ローカル確認:

```bash
cd 20261031
python3 -m http.server 8000
```

`http://localhost:8000/eigyo5/` を開く。Googleシートの取得に失敗した場合は、`eigyo4/data/prospects_seed.csv`へ読み取り専用でフォールバックする。

## Google自動化の設定

### 1. 個人用スプレッドシートを用意

新しいGoogleスプレッドシートを作る。公開シートとは分け、共有範囲を本人だけにする。

### 2. Apps Scriptへコードを登録

スプレッドシートの「拡張機能」→「Apps Script」を開く。

1. `gas-code.js` 全文を `コード.gs` に貼り付ける。
2. プロジェクト設定で「appsscript.json マニフェスト ファイルをエディタで表示する」を有効にする。
3. `appsscript.json` の内容を同名ファイルへ貼り付ける。
4. 保存し、スプレッドシートを再読み込みする。

### 3. 初期設定

シート上部の「営業AI v5」→「初期設定」を実行する。初回のみGoogleの権限確認が表示される。

作られるタブ:

- `候補企業`: 公開企業情報のキャッシュ
- `シグナル`: AIまたはルールで見つけた接点候補
- `関係・イベント`: 紹介、名刺、イベント、返信、商談などの非公開入力
- `営業進展`: 接点発見から有料検証までの進展
- `実行ログ`: 自動処理の結果

### 4. 通知先を設定

Apps Scriptの「プロジェクトの設定」→「スクリプト プロパティ」に追加する。

| プロパティ | 値 |
|---|---|
| `NOTIFY_EMAIL` | 自分が確認するGmailアドレス |

未設定時は、スクリプト実行者のメールアドレスを使用する。

### 5. Gemini無料枠を使う場合（任意）

Google AI StudioでAPIキーを発行し、スクリプトプロパティへ追加する。

| プロパティ | 値 |
|---|---|
| `GEMINI_API_KEY` | 発行したAPIキー |

未設定、無料枠超過、APIエラーの場合はルール判定へ自動で切り替わる。課金設定へ自動移行する処理はない。

注意: Gemini API無料枠では、送信内容がGoogle製品の改善に使われる場合がある。この実装は公開企業情報のみを送信し、`関係・イベント`の相手名、背景、非公開メモ、Gmail、カレンダー情報は送信しない。

### 6. 自動化を有効化

「営業AI v5」→「自動化トリガーを作成」を実行する。

- 毎週月曜8時台: 公開企業を調査し、条件を満たす場合だけ本人へ最大1件通知
- シート編集時: 関係・イベントの準備、本人が承認した下書き・予定の作成

## 承認操作

### 関係・イベント

1. 会社名と接点種別（紹介、イベント、名刺、返信、商談など）を記入する。
2. `準備内容`が自動生成される。これは非公開情報を外部AIへ送らないルール処理。
3. 予定日時を入力し、`状態`を `予定承認` にすると本人のGoogleカレンダーへ30分の予定を作る。

### シグナル

1. AI候補の根拠と文面を確認する。
2. 営業先のメールが公開企業データに登録済みの場合、`状態`を `下書き承認` にするとGmail下書きを作る。
3. 下書きは送信されない。宛先・内容を本人が確認して手動送信する。

## 安全設計

- 対外メールの自動送信は実装しない。
- 予定は明示的な `予定承認` がある場合だけ作る。
- 同じシグナルは指紋で重複排除する。
- 本人通知は7日間に最大1件。
- 通知を無視しても同じ内容を再送しない。
- Geminiには公開情報以外を送信しない。
- APIキーをHTML、GitHub、スプレッドシートのセルへ置かない。

## 2〜4週間の検証

毎週、次だけを記録する。

1. 調査に使った時間
2. 候補を「会う価値あり」と判断したか
3. 実際に会話したか
4. 課題・予算を確認できたか
5. 次回合意または有料検証へ進んだか
6. 動かなかった理由（意味が弱い、接点が不自然、時間がない、提案が重い等）

名刺枚数、通知開封数、電話件数、連続利用日数は成功指標にしない。
