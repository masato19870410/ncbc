# 営業AI v5｜アウトリーチ起点の根本再設計レビュー

調査日: 2026-11-01

## 結論

独立Webアプリ単体は推奨しない。現行v4は、公開情報を同じ形式で比較する成果物としては成立しているが、「アプリを思い出して開き、結果を読んで、自分で営業を始める」負担を残している。

v5は、公開画面を比較・説明の場に限定し、普段使うGoogle Sheets、Gmail、Googleカレンダーへ準備済みの仕事を届ける併用型とする。ただし、通知そのものを価値にしない。「会う理由・相手の期待効果・予算が生まれる条件・15分以内の一歩」が揃わなければ通知しない。

## 1. 現行営業AIの問題点

- 実行時の生成AI、通知、営業履歴、フォロー管理がなく、実態は企業比較データベースである。
- 求人・Webの弱点から提案を作るが、「どう自然に会うか」が電話・メール中心だった。
- 企業カードを読んだ後、接触の意味、予算、関係経路をユーザー自身が考える必要がある。
- Googleシート更新は楽になったが、アプリを開く理由は増えていない。
- 金額は人材紹介費等の参考試算で、実際の利用状況・採用人数・粗利を確認するまでROIではない。
- 旧版にはGitHub Actionsの定期調査案があるが、停止経験のあるSupabase保存を前提とし、現行v4へ接続されていない。

## 2. 実用的なトリガーとシグナル

シグナルは「営業する理由になり得る外部変化」、トリガーは「AI処理を開始するイベント」と分ける。

| 種類 | 例 | 検知 | 優先度 |
|---|---|---|---|
| 外部シグナル | 地域イベント登壇、業界団体活動、新規事業、求人変化、広報更新 | 週次の公開情報調査 | 高 |
| 関係シグナル | 紹介可能な知人、過去案件、同じコミュニティ、類似顧客 | 本人の非公開シート | 高 |
| イベントトリガー | 紹介、名刺、イベント予定、返信、商談登録 | Sheetsの編集 | 高 |
| 定期トリガー | 既存候補の変化確認 | 週1回 | 中 |
| 弱いトリガー | 毎朝、理由なく候補を送る | 時刻 | 不採用 |

名刺取得をKPIにすると質の低い交流会参加を促すため、起動イベントには使えても成果指標にはしない。

## 3. ユーザー向けアウトリーチ

AIから本人への通知は、次のゲートを全て満たした候補だけにする。

1. 確認可能な公開根拠がある。
2. 売り込み以外の自然な接点がある。
3. 相手にとっての期待効果を説明できる。
4. 予算化の条件または未確認事項が分かる。
5. 次の一歩が15分以内で開始できる。

SDTの観点では、接触方法とタイミングを本人が選ぶ自律性、準備済みの下書きによる有能感、紹介・コミュニティによる関係性を守る。ZPDの観点では、「営業する」ではなく「イベントを1件選ぶ」「紹介可能か1人に聞く」まで課題を小さくする。

無視された場合は督促しない。目的、効果、予算、接点のどれが弱いか再評価し、改善できなければ保留する。

## 4. 営業先向けアウトリーチ

優先順位は固定せず、関係性と目的で選ぶ。

1. 紹介・コミュニティ: 地方で信頼を借りられる場合の第一候補。
2. イベント・講師・取材: 相手の活動を理解してから会話でき、本人の対面志向にも合う。
3. SNS・DM: 公開活動への反応から始められる場合。
4. メール・フォーム: 根拠と短いヒアリング依頼が揃う場合。
5. 電話: 他の接点がなく、目的と台本が具体的な場合。

接触前に連絡先、根拠、質問、最小提案を準備する。接触後は課題確認、予算確認、次回合意、有料検証の順に進める。対外送信は常に本人承認とする。

## 5. ゲーム化の価値とリスク

電話件数、メール件数、名刺枚数、ログイン連続日数は採用しない。活動量が増えても質の悪いアポと疲労が増える可能性がある。

可視化するのは「接点発見→対話→課題確認→予算確認→次回合意→有料検証」の進展だけとする。順位、罰、ストリーク、他者比較は導入しない。進展表示がプレッシャーになる場合は非表示にする。

## 6. 離脱の壁を減らす改善策

| 段階 | 主な壁 | v5の対応 |
|---|---|---|
| 思い出す | 独立アプリを忘れる | 条件成立時だけGmailへ最大週1件 |
| 開く | URLを開く意味が弱い | メール本文に根拠と一歩を含める |
| ログイン | 新規アカウントが面倒 | Google環境を利用し専用ログインを作らない |
| 入力 | 企業情報の手入力 | 公開シートを同期。関係イベントだけ最小入力 |
| 考える | 何をするか曖昧 | 15分以内の次の一歩を1つ提示 |
| 待つ | AI処理待ち | 週次で事前処理し結果だけ届ける |
| 理解する | 長文・根拠不明 | 確認済み、仮説、未確認を分離 |
| 判断する | 費用対効果が曖昧 | 期待効果と予算条件を並べる |
| 行動する | 連絡が重い | 紹介・イベント・取材を先に比較 |
| 再利用 | 通知に慣れて無視 | 重複排除、週1件上限、同文再送なし |

## 7. 独立アプリが必要か

独立アプリだけでは不要。10社を比較し、他者へ構想を説明する公開画面には価値がある。一方、日常の起動、通知、承認、フォローはGoogle環境の方が適している。

比較:

| 提供形態 | 運用 | 通知 | 入力負担 | 継続性 | 結論 |
|---|---|---|---|---|---|
| A 独立Web | 認証・バックエンドが必要 | 弱い | 高い | 開かれにくい | 単独採用しない |
| B ChatGPTスケジュール＋Google | 会話に強い | アカウント機能に依存 | 低い | ChatGPT利用時は高い | 補助利用 |
| C Gmail/Sheets/Calendar | 無料枠で小規模運用可能 | 強い | 低い | 既存習慣に合う | 実働の中心 |
| D 併用 | 境界設計が必要 | 強い | 低い | 高い | 採用 |

ChatGPTのScheduled tasksは時刻実行や対応アプリのイベント起動が可能だが、利用可能なイベントと上限はプランに依存するため、MVPの必須基盤にはしない。([OpenAI Scheduled tasks](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt))

## 8. 最小構成のMVP

- 公開v5: 現行10社を会う理由・接点・期待効果・予算条件から比較。
- 個人Sheets: 公開候補、シグナル、関係イベント、進展、ログ。
- Apps Script: 月曜の週次調査、編集イベント、本人通知、承認後の下書き・予定。
- Gemini: 公開情報だけを分析。未設定・失敗時はルール判定。
- Gmail/Calendar: 送信・登録前に本人承認。

## 9. 実装優先順位

1. v4を固定し、v5公開画面を分離する。
2. Sheetsの状態管理と承認境界を作る。
3. 週次調査、重複排除、週1件通知を実装する。
4. 関係イベントから準備内容を作る。
5. 承認済みGmail下書きと予定を作る。
6. 実地データから接点・提案ロジックを更新する。
7. 個人で勝ち筋が確認できた後だけ、ギルド・チーム共有を検討する。

## 10. 実際の営業業務での検証

2〜4週間、毎週最大1候補で検証する。

- AIを開かずに準備された候補数
- 1候補あたりの調査時間
- 「会う価値あり」と判断した割合
- 実際の対話数
- 課題・予算を確認できた割合
- 次回合意、有料検証、受注への進展
- 動かなかった理由

成功条件は通知開封ではなく、手作業の調査時間が減り、自然な接点から課題・予算の会話へ進むこと。4週間で対話が生まれなければ、通知回数を増やさず、対象企業・接点・商品仮説を見直す。

## 公式仕様と運用上の制約

- Apps Scriptは時間主導・編集イベントのインストール型トリガーを利用できる。([Google Apps Script triggers](https://developers.google.com/apps-script/guides/triggers/installable))
- Apps Scriptには実行時間、メール送信先数、トリガー数等の割当がある。小規模な週次MVPは範囲内だが、上限は変更され得る。([Google Apps Script quotas](https://developers.google.com/apps-script/guides/services/quotas))
- Gmail下書きとCalendar予定はApps Scriptで作成できる。([GmailApp](https://developers.google.com/apps-script/reference/gmail/gmail-app), [Calendar service](https://developers.google.com/apps-script/reference/calendar))
- Gemini APIには無料枠があるが、無料サービスへ送信した内容が製品改善に使われ得る。そのため公開情報だけに限定する。([Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing), [Gemini API terms](https://ai.google.dev/gemini-api/terms))
